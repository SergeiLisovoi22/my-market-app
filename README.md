# My Market App — Яндекс Практикум, спринт 6

Реактивная версия принятого проекта спринта 5 «Витрина интернет-магазина».

## Стек

- Java 21, Gradle 8.8 (Wrapper), Spring Boot 3.3.13
- **Spring WebFlux** и Reactor (`Mono`, `Flux`), встроенный **Reactor Netty**
- **Spring Data R2DBC**, реактивный драйвер **H2 R2DBC**
- Thymeleaf, HTML-формы, Post/Redirect/Get
- JUnit 5, `WebTestClient`, `StepVerifier`, `@DataR2dbcTest`
- Docker

Зависимостей Spring MVC, Spring Data JPA и Hibernate ORM нет. Доступ к базе данных в HTTP-запросах реактивный; `block()` используется только при начальном заполнении каталога (startup) и в тестах.

## Запуск

Windows PowerShell, в корне репозитория:

```powershell
.\gradlew.bat clean test
.\gradlew.bat bootRun
```

Linux/macOS:

```bash
./gradlew clean test
./gradlew bootRun
```

Откройте http://localhost:8080/items.

### Docker

Сначала собрать JAR:

```powershell
.\gradlew.bat clean bootJar
docker build -t my-market-app:sprint6 .
docker run --rm -p 8081:8080 my-market-app:sprint6
```

После этого откройте http://localhost:8081/items. Можно использовать `docker compose up --build` после `bootJar`.

## База данных

Используется **H2 in-memory с реактивным драйвером**, URL `r2dbc:h2:mem:///marketdb;DB_CLOSE_DELAY=-1`. В спринте 6 база в памяти разрешена заданием. Данные **не сохраняются после остановки приложения**. Схема создаётся из `src/main/resources/schema.sql`; примеры товаров добавляются при первом запуске.

R2DBC не поддерживает JPA-связи: таблицы `cart_lines` и `order_lines` хранят внешние ключи (`item_id`, `order_id`). Сервисы явно загружают связанные записи. Корзина одна для учебного приложения, как в спринте 5.

## Функциональность

- `/` и `/items` — витрина, поиск, сортировка `NO`/`ALPHA`/`PRICE`, пагинация (2/5/10/20/50/100)
- `/items/{id}` — карточка товара
- `/cart` и `/cart/items` — корзина
- `/orders` — история заказов и общий итог
- `/orders/{id}` — детали заказа с изображениями
- `POST /buy` — оформление покупки
- `/admin/items/import` — импорт CSV
- `/images/{filename}` — изображения из ресурсов приложения

Формат CSV (UTF-8): `title;description;price;imgPath`. Пример — `samples/catalog.csv`. Сначала проверяются все строки, затем данные записываются в одной реактивной транзакции. При ошибке импорт не изменяет каталог.

Изменения корзины и покупка выполняются под общей блокировкой `cart_mutex` (`SELECT ... FOR UPDATE`) внутри `TransactionalOperator`. Это защищает общую корзину от гонок и обеспечивает атомарность оформления заказа и очистки корзины. Денежные суммы проверяются через `Math.multiplyExact` и `Math.addExact`.

При слишком большом `pageNumber` возвращается HTTP 400, а допустимая пустая страница показывает ссылку на начало каталога.

## Тестирование

```powershell
.\gradlew.bat clean test
```

Отчёт: `build/reports/tests/test/index.html`.

Тесты включают:
- реактивный слой доступа к данным (`@DataR2dbcTest`, `StepVerifier`);
- работу WebFlux-контроллеров через `WebTestClient`;
- корзину, оформление покупки и сохранение заказов;
- обработку больших номеров страниц;
- предварительную проверку CSV и отсутствие частичного импорта;
- ограничения цен и переполнение сумм.

## Доработки по ревью спринта 6

- Интеграционные тесты используют фиксированные товары, проверяют HTML через Jsoup, точные количества и суммы, POST/Redirect/GET, историю заказов, все шесть размеров страниц и multipart-импорт. Полные интеграционные тесты используют один профиль `test` и общий контекст.
- Поисковое значение в редиректе кодируется как URI-переменная (`+` → `%2B`). Раскладка карточек выполняется в HTML/CSS, сервис отдаёт плоский список.
- Лимит CSV задаётся `app.catalog-import.max-bytes` (по умолчанию 5242880 байт / 5 МиБ). При превышении приложение возвращает HTTP 413. Предел буферизации multipart настраивается отдельно.
- `MoneyException` отделяет денежные вычисления от HTTP; веб-слой преобразует ошибку в HTTP 400.
- Чтение непустой корзины и подготовка заказа используют пакетную загрузку товаров по идентификаторам (два SELECT вместо 1+N при чтении); история заказов загружает позиции одним IN-запросом после чтения заголовков. Блокировка корзины при изменениях и покупке сохранена.
- В `schema.sql` добавлены CHECK для цены, количества и суммы заказа в соответствии с ограничениями приложения.
