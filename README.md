# My Market App — Sprint 5 (Java 21 / Spring Boot)

Учебный проект «Витрина интернет-магазина» по заданию Яндекс Практикума.
Макет страниц сохранён; добавлены backend, H2, JPA, тесты и Docker.

## Требования

- Java 21 (например, Amazon Corretto 21)
- Gradle Wrapper 8.8 входит в проект, отдельная установка Gradle не требуется
- Для Docker-запуска: Docker Desktop

## Локальный запуск

1. Открыть директорию `my-market-app` в IntelliJ IDEA как **Gradle**-проект.
2. В настройках Gradle выбрать JDK 21.
3. В терминале IntelliJ IDEA выполнить `.\gradlew.bat bootRun` (Windows PowerShell) или `./gradlew bootRun` (Linux/macOS).
4. Открыть <http://localhost:8080/items>.

В архиве уже присутствуют `gradlew`, `gradlew.bat`, `gradle/wrapper/gradle-wrapper.jar` и `gradle-wrapper.properties`: добавьте их в Git. При первом запуске Wrapper скачает Gradle 8.8, если дистрибутив ещё не закеширован.

При первом запуске создаются 6 демонстрационных товаров. База H2 файловая:
`./data/marketdb` (состояние сохраняется между запусками).

## Тесты и JAR

```bash
./gradlew clean test
./gradlew bootJar
java -jar build/libs/my-market-app-0.0.1-SNAPSHOT.jar
```

На Windows PowerShell используйте `.\gradlew.bat` вместо `./gradlew`.
Отчёт о тестах: `build/reports/tests/test/index.html`.

## Docker

```bash
./gradlew bootJar
docker compose up --build
```

Приложение доступно по адресу <http://localhost:8080/items>.
База данных сохраняется в именованном Docker-томе `market-data`.

## Страницы и действия

- `GET /`, `GET /items` — витрина, поиск, сортировка, пагинация.
- `POST /items` — изменение количества товара (PLUS/MINUS), редирект на витрину.
- `GET /items/{id}`, `POST /items/{id}` — карточка товара и действия с корзиной.
- `GET /cart`, `GET /cart/items`, `POST /cart/items` — корзина (PLUS/MINUS/DELETE).
- `GET /orders`, `GET /orders/{id}` — список заказов и детали.
- `POST /buy` — сохранение заказа и очистка корзины в одной транзакции.
- `GET /images/{filename}` — локальные изображения товаров.
- `GET /admin/items/import`, `POST /admin/items/import` — простой импорт товаров из CSV.

CSV: `title;description;price;imgPath`. Образец: `samples/catalog.csv`.
В импорте сначала проверяются все непустые строки и только затем сохраняются записи;
ошибки отображаются на странице импорта с номером строки.
Для файлов изображений в данном MVP используются локальные SVG.

## Архитектура

`web (MVC) → service (бизнес-логика) → Spring Data JPA → H2`.
Представления получают неизменяемые DTO, не JPA-сущности.
Товар, корзина и заказ разделены по пакетам. При покупке сохраняются
снимки названий, цен и путей к изображениям (изменение товара позже не влияет на старый заказ).

## Исправления по замечаниям ревьюера

- Список заказов отображает также суммарную стоимость всех заказов.
- Изображение товара сохраняется в позиции заказа при оформлении покупки.
- Корзина одна общая: для её изменения и оформления заказа используется одна строка
  `cart_mutex` с JPA-пессимистической блокировкой. Это учебное решение для
  последовательной обработки запросов (без разделения корзин по пользователям).
- После POST-изменения корзины используется редирект (Post/Redirect/Get).
- CSV проверяется целиком до сохранения; ошибки показываются на форме.
- Цена товара: 0–1 000 000 000 руб., количество: максимум 1000 шт. на товар;
  суммы считаются через `Math.multiplyExact()` и `Math.addExact()`.
- В новой версии у `order_lines` появляется nullable-поле `img_path` — старые
  позиции заказа могут не иметь изображения. Для существующей H2-базы рекомендуется
  сделать резервную копию папки `data/` перед первым запуском нового кода.
- При доработке открытого Pull Request достаточно одного исправляющего коммита
  в `feature/sprint5-market`, без merge в `main`.

## Дополнительные проверки перед отправкой ревьюеру

- Запустить `.\gradlew.bat clean test` на JDK 21 и убедиться, что новые тесты проходят.
- Проверить, что `build/`, `.gradle/`, `.idea/` и файлы из `data/` не попали в Git.
- Проверить Docker-сборку **после** `bootJar`, затем открыть `/items` в браузере.
- Создать историю небольших коммитов в рабочей ветке и отправить её в GitHub.

## Допущения

- Учебное приложение **без регистрации/авторизации**: корзина одна общая (не персональная).
- Для упрощения используется Hibernate `ddl-auto=update`; в production желательно Flyway/Liquibase.
- Импорт CSV поддерживает простой формат с `;` как разделителем, без экранирования.
- Bootstrap 5 и Bootstrap Icons загружаются через CDN, поэтому их оформление требует доступа к интернету; логика приложения локальна.
- Не выполнять `git init` в копии, если проект уже клонирован из GitHub: коммиты делать в своём репозитории.
